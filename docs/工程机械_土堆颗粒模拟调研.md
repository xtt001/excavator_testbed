# 工程机械模拟中 土堆与颗粒模拟的调研与对接思路

我整理了可用的颗粒或土堆仿真方案，目标是从现有 MuJoCo 刚体环境迁移或并行引入更真实的土壤物理。

---

## 0. 背景与结论

当前 MuJoCo 场景以刚体接触为主，难以表达铲斗挖起土堆并装载的真实效果。  
这是物理模型能力上限。需要支持颗粒 DEM 或连续介质 MPM 的引擎。

---

## 1. AGX Dynamics 工业级多体与接触

### 1.1 核心能力

- 多体动力学与接触质量高，适合工程级验证
- 提供 Python API 与教程

### 1.2 关键 API

AGX 的核心是 `agxSDK::Simulation`，通过 `add(...)` 挂载对象与约束  

- `agxSDK::Simulation.add(agx::RigidBody* body)`  
- `agxSDK::Simulation.add(agxCollide::Geometry* geometry)`  
- `agxSDK::Simulation.add(agx::Constraint* constraint)`  
- `agxSDK::Simulation.add(agx::ContactMaterial* material)`

参考  

- Python 教程 [https://www.algoryx.se/documentation/complete/agx/tags/latest/doc/main/python_tutorials.html](https://www.algoryx.se/documentation/complete/agx/tags/latest/doc/main/python_tutorials.html)  
- `agxSDK::Simulation` [https://www.algoryx.se/documentation/complete/agx/html/doc/html/classagxSDK_1_1Simulation.html](https://www.algoryx.se/documentation/complete/agx/html/doc/html/classagxSDK_1_1Simulation.html)

### 1.3 接入当前项目的思路

1. 保留控制策略与数据结构，仅替换物理引擎
2. 在 AGX 中构建挖掘机刚体系统与铲斗，配置接触材料
3. 如需颗粒土堆，确认 AGX 是否具备对应模块或扩展
4. 每步写入关节目标，推进仿真，读回 `qpos/qvel/images`，录 HDF5

### 1.4 切换难度

中高。商业授权与部署成本高，但动力学质量最好

---

## 2. Project Chrono 推荐 DEM 颗粒

### 2.1 核心能力

- Chrono::Granular 与 Chrono::GPU 提供离散元颗粒系统  
- 支持大量颗粒与 GPU 加速

### 2.2 关键 API

核心类  

- `chrono::gpu::ChSystemGpu`  
  - 构造 `ChSystemGpu(radius, density, box_dims)`  
  - 设置颗粒 `SetParticles(pos, vel, omega)`  
  - 读粒子文件 `ReadParticleFile(...)`  
  - 设重力 `SetGravitationalAcceleration(...)`  
  - 边界 `CreateBCPlane(...)`
- `chrono::granular::ChSystemGranularSMC`

参考  

- `ChSystemGpu` [https://api.projectchrono.org/classchrono_1_1gpu_1_1_ch_system_gpu.html](https://api.projectchrono.org/classchrono_1_1gpu_1_1_ch_system_gpu.html)  
- `ChSystemGranularSMC` [https://api.projectchrono.org/classchrono_1_1granular_1_1_ch_system_granular_s_m_c.html](https://api.projectchrono.org/classchrono_1_1granular_1_1_ch_system_granular_s_m_c.html)

### 2.3 接入当前项目的思路

1. 用 Chrono 复建挖掘机刚体，或导入 CAD 与 URDF
2. 初始化土堆颗粒场
  - `SetParticles(...)` 或 `ReadParticleFile(...)`  
  - 设置边界、重力与接触材料参数
3. 每步写入关节目标，`DoStepDynamics(dt)` 推进，读回状态并写 HDF5
4. 训练侧保持不变，动作维度与关节一致

### 2.4 切换难度

中。工程成本可控，颗粒物理成熟，最贴合挖掘场景

---

## 3. NVIDIA Isaac Sim 与 Omni PhysX GPU 粒子

### 3.1 核心能力

- Omni PhysX 提供 GPU PBD 粒子系统，可模拟颗粒介质与流体  
- 粒子可与刚体与关节系统交互，GPU-only

### 3.2 关键 API

粒子仿真需要三个组件，USD Stage 中创建  

1. Particle System
2. Particle Set 或 PointInstancer
3. PBD Particle Material

参考 [https://docs.omniverse.nvidia.com/kit/docs/omni_physics/106.5/dev_guide/particles/particles.html](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/106.5/dev_guide/particles/particles.html)

### 3.3 接入当前项目的思路

1. 在 Isaac Sim 中搭建挖掘机 articulation 与粒子土堆
2. 配置 PBD 粒子材料的密度与摩擦
3. 每步写入关节目标，推进，读回状态并录 HDF5

### 3.4 切换难度

高。平台重，依赖 GPU，但粒子系统开箱即用

## 4. Taichi MPM 连续介质

### 4.1 核心能力

- MPM 擅长土壤、雪与泥等连续介质  
- Taichi 提供 MPM 示例与材料模型

### 4.2 关键 API

典型 MPM 子步  

1. P2G
2. Grid Update
3. G2P

参考 [https://github.com/taichi-dev/taichi/blob/master/python/taichi/examples/ggui_examples/mpm128_ggui.py](https://github.com/taichi-dev/taichi/blob/master/python/taichi/examples/ggui_examples/mpm128_ggui.py)

### 4.3 接入当前项目的思路

1. 用 Taichi 实现土堆与地形场
2. 自行实现挖掘机与土堆耦合
3. 控制接口需自定义并输出 HDF5

### 4.4 切换难度

很高。适合研究，不适合快速工程落地

## 5. Bullet 与 PyBullet 软体为主

### 5.1 核心能力

- 提供软体 `btSoftBody` 与刚体耦合  
- 颗粒真实性有限

参考 [https://pybullet.org/Bullet/BulletFull/classbtSoftBody.html](https://pybullet.org/Bullet/BulletFull/classbtSoftBody.html)

### 5.2 切换难度

中等，但真实性不足，不推荐作为挖土主力

## 6. 与当前训练流程的对接总览

当前训练依赖的 HDF5 结构  

- `/observations/qpos`  
- `/observations/qvel`  
- `/action`  
- `/observations/images/*`

任意引擎迁移只需保证接口语义一致  

1. `reset()` 返回初始观测
2. `step(action)` 推进 dt，返回 `qpos/qvel/images`
3. 录制 HDF5，复用现有训练与评估脚本

## 8. API 调用顺序与伪代码

### 8.1 AGX Dynamics 调用顺序

1. 创建 `agxSDK::Simulation`。
2. 创建挖掘机刚体和几何体，加入仿真。
3. 创建关节约束和驱动器，加入仿真。
4. 创建地面、边界和接触材料。
5. 初始化土堆表示。若使用颗粒模块则创建颗粒体，否则加载等价介质。
6. 进入控制循环。每步执行写动作、推进仿真、读状态、写日志。

伪代码如下。

```python
sim = agxSDK.Simulation()

excavator = build_excavator_bodies_and_joints()
sim.add(excavator.root_body)
for body in excavator.bodies:
    sim.add(body)
for c in excavator.constraints:
    sim.add(c)

ground = create_ground_geometry()
sim.add(ground)
for cm in create_contact_materials():
    sim.add(cm)

soil = init_agx_soil_field(sim)

dt = 0.02
obs = reset_state(sim, excavator, soil)
for t in range(horizon):
    action = policy(obs)
    apply_joint_targets(excavator, action)
    sim.stepForward(dt)
    obs = read_observation(sim, excavator)
    write_hdf5_step(obs, action)
```

### 8.2 Project Chrono 调用顺序

1. 创建 `ChSystemGpu` 或 `ChSystemGranularSMC`。
2. 设置重力、接触参数、边界。
3. 初始化颗粒位置和速度。
4. 初始化挖掘机刚体和关节驱动。
5. 进入控制循环。每步执行写动作、推进、读状态、写日志。

伪代码如下。

```python
sys = chrono.gpu.ChSystemGpu(radius, density, box_dims)
sys.SetGravitationalAcceleration(chrono.ChVector3d(0, 0, -9.81))
create_boundaries(sys)

pos, vel, omg = make_initial_particles()
sys.SetParticles(pos, vel, omg)

excavator = build_excavator_multibody()
attach_excavator_to_chrono(excavator, sys)

dt = 0.02
obs = reset_state(sys, excavator)
for t in range(horizon):
    action = policy(obs)
    apply_joint_targets(excavator, action)
    sys.DoStepDynamics(dt)
    obs = read_observation(sys, excavator)
    write_hdf5_step(obs, action)
```

### 8.3 Isaac Sim 调用顺序

1. 创建 Physics Scene。
2. 创建挖掘机 articulation。
3. 创建 Particle System、Particle Set、PBD Material。
4. 绑定材料并设定粒子参数。
5. 进入控制循环。每步执行写动作、步进、读状态、写日志。

伪代码如下。

```python
stage = open_stage()
scene = create_physics_scene(stage)
robot = create_excavator_articulation(stage)

psys = create_particle_system(stage)
pmat = create_pbd_material(stage, friction=0.8, cohesion=0.1)
bind_material(psys, pmat)
create_particle_set_from_mesh(stage, psys, source_mesh="/World/SoilPile")

obs = reset_state(stage, robot)
for t in range(horizon):
    action = policy(obs)
    set_articulation_targets(robot, action)
    step_simulation(dt)
    obs = read_observation(stage, robot)
    write_hdf5_step(obs, action)
```

## 9. 粒子场初始化脚本模板

### 9.1 Chrono 模板

```python
def make_chrono_soil(sys, n, x_rng, y_rng, z0, spacing):
    pos = []
    vel = []
    omg = []
    for i in range(n):
        x = x_rng[0] + (i % 100) * spacing
        y = y_rng[0] + ((i // 100) % 100) * spacing
        z = z0 + (i // 10000) * spacing
        pos.append(chrono.ChVector3f(x, y, z))
        vel.append(chrono.ChVector3f(0, 0, 0))
        omg.append(chrono.ChVector3f(0, 0, 0))
    sys.SetParticles(pos, vel, omg)
```

### 9.2 AGX 模板

```python
def make_agx_soil(sim, cfg):
    soil = []
    for p in sample_particles(cfg.count, cfg.region):
        rb = agx.RigidBody()
        geom = agxCollide.Geometry(agxCollide.Sphere(cfg.radius))
        rb.add(geom)
        rb.setPosition(p.x, p.y, p.z)
        sim.add(rb)
        soil.append(rb)
    return soil
```

### 9.3 Isaac Sim 模板

```python
def make_isaac_soil(stage, particle_system_path, source_mesh_path):
```

## 10. 与 `record_sim_episodes.py` 对接的接口层设计

### 10.1 设计目标

- 不改训练脚本的数据格式。  
- 只替换仿真后端。  
- 保持 `qpos/qvel/action/images` 语义一致。

### 10.2 统一环境接口

```python
class ExcavationEnvAdapter:
    def reset(self) -> dict:
        ...
    def step(self, action) -> dict:
        ...
    def render(self) -> dict:
        ...
```

返回字段要求如下。

```python
obs = {
    "qpos": np.ndarray,      # shape=(state_dim,)
    "qvel": np.ndarray,      # shape=(state_dim,)
    "images": {"top": np.ndarray},  # HWC uint8
    "env_state": np.ndarray  # 可选，用于记录土堆或目标状态
}
```

### 10.3 在录制脚本中的最小改动点

1. 把 `make_ee_sim_env` 和 `make_sim_env` 抽象成工厂函数。
2. 新增参数 `--sim_backend`，可选 `mujoco`、`chrono`、`agx`、`isaac`。
3. 在录制主循环内不改业务逻辑，只调用统一接口。

示例。

```python
env = make_env(task_name, equipment_model, sim_backend=args.sim_backend)
ts = env.reset()
for step in range(episode_len):
    action = policy(ts)
    ts = env.step(action)
    save_step(ts, action)
```

### 10.4 HDF5 字段映射规则

- `action`：始终保存控制目标，挖掘机场景建议为 4 关节目标。  
- `qpos/qvel`：保存可观测的关节状态。  
- `images/top`：统一相机名称，保证训练侧无需改相机键名。  
- `env_state`：可扩展保存土堆体积分数、颗粒统计量、目标装载量。
