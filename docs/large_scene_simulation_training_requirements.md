# 大场景仿真算法训练侧需求

状态：草案

本文面向仿真侧同事，说明从算法训练和评测角度，我们希望大场景仿真第一阶段提供哪些能力。
本文只定义需求和验收口径，不限定具体 Unity / AGX 实现方式。

## 1. 背景

当前智能挖机算法侧已经在单挖机场景中形成了基本范式：

- 仿真环境提供可交互场景和稳定状态输出。
- 算法侧通过遥操作、脚本、planner 或策略进行 episode 采集。
- 数据以 episode 为单位保存，用于 ACT 等模仿学习训练。
- rollout 后需要有日志、事件、指标和失败原因，方便判断问题来自数据、任务、planner、策略还是仿真接口。

下一阶段希望从单台挖掘机作业扩展到更接近真实矿山/工地的大场景：

- 挖掘机负责挖掘、装载或向指定区域转移物料。
- 装载机作为新的重要设备，需要从第一版场景中纳入。
- 重卡作为运输对象，需要具备进场、停靠、受料、满载和离场等任务语义。

算法侧关注的重点不是视觉上做一个很大的展示场景，而是获得一个可以训练、可以评测、可以记录、可以逐步扩展的多设备作业 testbed。

## 2. 第一版场景范围

第一版建议包含以下实体：

- 一台挖掘机。
- 一台装载机。
- 一辆重卡。
- 一个或多个料堆 / 作业区。
- 一个重卡停靠与装载区。
- 一个装载机可行驶和作业的区域。
- 基本通道、边界和安全区域。

第一版不要求一次性实现完整矿山级调度，也不要求三类设备都具备复杂智能行为。更重要的是先让这些实体在同一场景中具有清楚的任务边界、状态输出和事件记录。

## 3. 任务闭环需求

从算法训练角度，大场景至少需要支持以下几类任务闭环。

### 3.1 挖掘机单机闭环

保留当前单挖机任务语义，作为新场景中的基础能力：

```text
挖掘 -> 携带/转运 -> 倾倒 -> 返回 -> 下一轮
```

该能力用于保证大场景不会破坏已有算法训练范式，也方便后续把新场景与旧场景做对照实验。

### 3.2 挖掘机向重卡装载

需要支持挖掘机将物料装入重卡车斗，并记录每次装载事件：

```text
重卡到位 -> 挖掘机挖料 -> 挖掘机向重卡倒料 -> 重卡载重增加 -> 多轮装载 -> 满载/达到阈值
```

算法侧需要知道：

- 重卡是否已经到达可装载位置。
- 挖掘机是否成功把物料倒入重卡。
- 每次有效装入重卡的物料量。
- 是否有漏料、碰撞、未命中车斗等失败情况。
- 重卡是否达到离场阈值。

### 3.3 装载机参与作业

装载机第一版需要作为可训练、可评测的设备进入场景。它可以先支持简化任务，但需要保留后续扩展空间。

第一阶段希望装载机至少具备以下任务语义中的一部分：

- 从指定料堆取料。
- 将物料运送到指定区域。
- 将物料倒入重卡或中转区域。
- 在场景中移动、靠近、停靠、等待。
- 与挖掘机和重卡共享作业区域时具备基本碰撞和阻塞事件记录。

如果第一版还不能完整支持装载机铲料和倒料，也希望先提供可控移动、可停靠、可记录状态的占位能力，便于算法侧提前设计多设备调度接口。

### 3.4 多设备协同闭环

长期目标是支持多设备协同作业，例如：

```text
重卡进场并停靠
挖掘机或装载机进行装载
重卡达到载重阈值
重卡离场
下一辆重卡进入
```

第一版不要求所有环节都自动化，但需要从场景设计上保留这些任务事件和状态。

## 4. 算法侧需要的状态信息

大场景需要提供稳定、可记录、可用于训练和评测的状态信息。具体字段可以后续共同细化，第一版需要覆盖以下类别。

### 4.1 设备自身状态

每台设备都应有自己的状态输出：

- 设备位置和姿态。
- 关键关节或运动部件状态。
- 当前速度或运动趋势。
- 当前是否可控、是否卡住、是否正在执行任务。
- 当前所在区域或相对目标区域的位置关系。

### 4.2 物料状态

物料状态是训练和评测的关键。需要尽量提供：

- 挖掘机铲斗内物料量。
- 装载机铲斗内物料量。
- 重卡车斗内物料量。
- 料堆剩余量或局部变化趋势。
- 物料是否成功从一个容器转移到另一个容器。
- 漏料、非目标区域沉积、异常掉料等事件。

不要求第一版物料仿真完全真实，但需要有稳定的可观测指标，否则算法侧无法判断一次动作是否有效。

### 4.3 场景区域状态

场景中需要有清楚的语义区域：

- 挖掘作业区。
- 装载机取料区。
- 重卡停靠区。
- 重卡受料区 / 车斗区域。
- 装载机行驶区。
- 安全边界和不可进入区域。

算法侧需要能判断设备与这些区域的相对关系，例如是否到位、是否越界、是否接近目标、是否处于可装载姿态附近。

## 5. 控制与交互需求

大场景需要支持算法侧以统一方式接入不同设备。

### 5.1 每台设备独立可控

挖掘机、装载机、重卡应尽量具备独立控制入口。算法侧后续可能会分别接入：

- 人工遥操作。
- 脚本 baseline。
- 规则 planner。
- ACT 或其他模仿学习策略。
- 上层大模型 planner 输出的高层任务指令。

第一版不要求每台设备都有完整学习策略，但需要支持未来逐步替换控制来源。

### 5.2 支持 episode 采集

算法侧需要以 episode 为单位采集数据。每条 episode 至少应能记录：

- 初始场景状态。
- 每一步设备状态。
- 每一步控制输入。
- 关键事件。
- 任务完成或失败原因。
- 结束状态。

如果一开始完整多设备 episode 过于复杂，可以先支持短 episode，例如：

- 装载机从 A 点移动到 B 点。
- 挖掘机完成一次向重卡倒料。
- 重卡进入停靠区并停止。

## 6. 事件日志需求

大场景必须有事件日志。算法训练侧后续会依赖事件日志做数据切分、质量检查、训练标签和 rollout 归因。

第一版建议至少记录以下事件类型：

- `truck_arrived`
- `truck_parked_ready`
- `truck_departed`
- `excavator_bucket_loaded`
- `loader_bucket_loaded`
- `material_deposited_to_truck`
- `material_deposited_to_ground`
- `truck_load_threshold_reached`
- `vehicle_blocked`
- `collision`
- `out_of_work_area`
- `timeout`
- `episode_success`
- `episode_failed`

事件需要包含发生时间、相关设备、相关区域和必要的数值信息，例如本次转移了多少物料。

## 7. 评测指标需求

大场景 rollout 后需要能输出可比较的指标。第一版建议包括：

- 单次装载有效物料量。
- 重卡累计载重。
- 达到载重阈值所需时间。
- 挖掘机等待时间。
- 装载机等待时间。
- 重卡等待时间。
- 设备空动作时间。
- 碰撞次数。
- 越界次数。
- 漏料或非目标沉积量。
- episode 是否成功。
- 失败原因。

这些指标不一定一开始全部精确，但需要有稳定定义，方便算法侧持续做实验对比。

## 8. 视觉与传感需求

为了后续训练 VLA、VLM 或其他视觉策略，大场景需要保留视觉观察能力。

第一版希望支持：

- 至少一个全局观察视角，用于理解设备和场景关系。
- 每台主要设备可选的自车/第一视角或操作视角。
- 图像帧与状态、动作、事件在时间上可对齐。
- 相机配置尽量稳定，便于跨 episode 训练和评测。

第一版不要求相机数量很多，也不要求视觉效果完全真实，但需要保证图像能够反映任务关键信息，例如设备位置、料堆、车斗、装载区域和明显失败情况。

## 9. Reset 与可复现实验需求

算法训练需要大量重复实验，因此场景需要支持可复现 reset。

第一版希望支持：

- 重置设备初始位置。
- 重置料堆或至少提供近似一致的初始物料状态。
- 重置重卡位置和载重。
- 重置装载机状态。
- 重置事件和指标计数。
- 记录每次 episode 的场景配置。

如果物料完全 reset 成本较高，也可以先提供少数固定场景模板，但需要让算法侧知道当前 episode 属于哪个模板。

## 10. 数据兼容需求

大场景数据不需要一开始完全复用当前单挖机数据格式，但需要遵循同一类原则：

- episode 可独立读取。
- observation、action、event、metric 能对齐。
- 字段含义稳定。
- 场景配置和版本可追溯。
- 旧数据和新数据能区分。
- 后续可以接入 dataset QC、训练和 rollout 分析工具。

如果第一版字段还不稳定，可以先以草案形式输出，但需要避免每次运行随意改变字段含义。

## 11. 第一版交付物

从算法训练侧看，第一版希望仿真侧交付：

1. 一个可运行的大场景 demo。
2. 场景中包含挖掘机、装载机、重卡、料堆和关键作业区域。
3. 每台设备有基本状态输出和控制入口。
4. 场景可以 reset，并能重复运行 episode。
5. 至少支持一条简化任务闭环，例如重卡到位后接受一次或多次装载。
6. 能输出事件日志和基础评测指标。
7. 能提供至少一个稳定视觉观察视角。
8. 有一份字段说明，列出当前能输出的设备状态、物料状态、事件和指标。
9. 有一份已知限制说明，明确哪些能力只是占位、哪些物理效果尚未精细化。

## 12. 第一版验收口径

第一版验收不以“场景看起来是否完整”为唯一标准，而以是否能支撑算法训练闭环为主。

建议验收标准：

- 算法侧能启动场景、reset 场景并连续运行多条 episode。
- 每条 episode 都有可读取的状态、动作、事件和指标记录。
- 至少一类物料转移事件可以被稳定记录。
- 重卡载重或目标区域沉积量可以随任务推进变化。
- 挖掘机、装载机、重卡的状态可以在同一时间轴上对齐。
- 发生失败时，日志能区分碰撞、越界、未装载、超时等基本原因。
- 视觉观察能够看清主要设备和关键作业区域。

## 13. 非目标

第一版不要求：

- 完整矿山级交通调度。
- 多辆重卡连续自动排队。
- 装载机和挖掘机都具备高质量自主策略。
- 完全真实的颗粒级物料仿真。
- 真机级别的全部底层控制细节。
- 直接接入大模型。

这些可以作为后续阶段目标。第一版最重要的是建立多设备、大场景、物料转移、事件日志和算法训练闭环之间的接口基础。
